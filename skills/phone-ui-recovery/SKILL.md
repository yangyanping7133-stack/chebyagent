# 手机操作抗干扰

- 截图必须作为 GLM native image 原生图片输入处理；不要把图片证据转交给独立视觉 MCP。
- 点击、输入前确认最近观察的前台应用、目标控件和页面仍对应本次动作；发生切屏、滚动、键盘变化或用户操作后，旧坐标失效。重新获取页面与截图、定位目标，再继续。坐标必须明确属于实际屏幕还是本次截图，不能混用。
- 关键跳转后验证实际页面，不把工具返回“点击成功”当作业务成功。观察与点击之间仍可能发生变化，下一步必须根据新状态决定。
- 发现用户正在操作时让路，不抢回前台或连续点击。用有限的只读观察等待页面稳定；短暂干扰消失后，从新页面恢复。若持续被打断，简短说明并等用户交还操作，不无限重试。用户明确暂停或改变任务时遵从新指令。
- 恢复前保留当前条件、已核实条目与证据、待查项和下一步；沿用已有进度，不重复发起任务或从头搜索。当前页面无法确认是否已完成的动作先核对，尤其不要重复联系、预约、下单或支付。
- 切回聊天页只证明前台变了，不能据此断言目标应用崩溃、安全策略拒绝或跳转故障。区分观察事实与原因猜测。仅在用户不再操作、重新定位后仍复现，且有对应证据时报告故障；只读导航最多尝试两次恢复，仍失败则交代停点和已保留进度。
- 不新增笼统的权限拦截，也不扩大授权：付款、下单等沿用现有用户授权规则。不能用“恢复”绕过确认、自动提交或重试结果不明的交易。

这是模型执行约定，不是触摸互斥锁；不能保证消除截图与点击之间的竞态。没有真实运行证据时，不宣称已通过抗干扰验证。
